# Render 在线演示：待小组确认

状态：方案准备完成，尚未创建 Render 服务、连接账号、购买资源或生成可验证的线上地址。现有工业检测项目的 Render 不在本次操作范围内。

## 是否需要原仓库负责人操作

不必由负责人创建独立演示。你可以用自己的 GitHub Fork 与自己的 Render 服务，但连接仓库、分支和资源选择应由小组先协调。Render 连接 Git 提供商后，可对已授权仓库的指定分支启用自动部署；这取决于账号及 GitHub App 的仓库权限。[Render Git provider 文档](https://render.com/docs/git-provider)

如果仅通过公开 Git URL 手动部署，不能按已连接 GitHub 仓库的自动部署方式理解。自己的 Fork 也不会因为上游 main 更新而自行同步；需要先同步 Fork，再由所连接分支触发部署。[Render Web Services 文档](https://render.com/docs/web-services)

## 实际上线前还需完成的改造和验证

1. 固定要部署的道路项目提交与分支，核对模型权重路径和 CPU 依赖版本。
2. 增加独立的云端启动方式：监听 `0.0.0.0` 并读取 Render 的 `PORT`，使用该端口启动，不随意递增切换。当前本地入口默认监听 `127.0.0.1`，不能直接据此声称云端可用。[端口绑定要求](https://render.com/docs/web-services)
3. 明确权重、示例图及结果目录的构建和加载方式。仓库已有 18 张诊断样本；本机的 60 张案例库位于被 Git 忽略的本地目录，新云服务需另行构建或提供合法、可追溯的资源。
4. 在所选实例实际测量模型加载、单图/双模型推理、特征分析、18 张诊断的时长和内存，再确定可公开的功能。CPU 云服务的结果不能套用本机 GPU 测速。
5. 验证网页上传、图片显示、语言切换、图表独立刷新及 JSON 下载；核对缓存/临时文件的可写位置。需要持久保存的内容不能只依赖临时文件系统。[Render 免费服务说明](https://render.com/docs/free)
6. 验证重启与冷启动后仍可运行，再把实际服务地址加入 PPT 的在线演示入口。

## 为什么演讲仍要保留视频

Render 免费 Web 服务在连续 15 分钟无请求后会休眠，下一次访问唤醒通常约需一分钟。因此应在演示前唤醒并实际检查，85 秒字幕视频保留作离线演示选择。这里没有为避免等待而代替小组选择或购买付费资源。[Render 免费服务的休眠规则](https://render.com/docs/free)

当前交付 PPT 的第 19 页使用本地视频。若小组决定同时保留在线版，建议在完成上述上线验证后，再添加已核实的 URL；不要把部署方案或截图当成可运行服务。
